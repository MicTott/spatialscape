# Changelog

## Unreleased

- `tracks.genome: mm10` (or `mm39`) carries the mouse chromosome sizes like `hg38` does; a mouse ATAC sample no longer needs `chrom_sizes:`.

## 0.5.0 (2026-10-29)

- `spatialscape --version` prints the package's own version; an editable install used to show the metadata of whatever was first installed.
- **The Compare panel is a matrix.** Genes down, levels across (every cluster of a marker table, every cell type a contrast was fit in, the one column of a plain result), each cell the log2 fold change as a chip tinted by sign and size with padj, % in / out and rank on hover; each column head carries the level's legend colour, and clicking it focuses that level (lit as a column) and sorts by it. The panel has one title row (name, what was compared, a gene search, the method behind `i`), and the distribution beside the matrix has its own header (gene, the focused level in its colour, *only Astro on the map*) and a footer with the gene's numbers in that level. Beside it, for the gene on screen: violins of its expression per category, drawn from the per-cell values the maps use, when the levels are an annotation's categories, or the per-replicate dots with median and box when the comparison carries pseudobulk values. The build writes the matrix once (`matrix.zarr`, one float32 array per statistic). The violins show the comparison's levels and pool every other category into one "other", so a 48-category annotation stays readable; a level whose cells do not measure the gene on screen says so. Levels link to an annotation through the field's aliases too (the paper's `AI` is the bundle's `IA`). The *expression by annotation* dot plot follows the comparison's field, and its rows now carry each category's distribution. The amygdala example carries the manuscript's two marker tables (Supplementary Data 2, a ranked list per Visium spatial domain; Data 5, scran `findMarkers` for the three ITC subtypes) as `comparisons:` in `examples/amygdala.yaml`.
- **A Comparisons group in the side panel.** The comparison picker left the Samples group for a group of its own: one row per comparison with what it is (groups, levels, replicates), the active one carrying its level select and description, and a switch in the bar that closes the panel under the maps and reopens the last one.
- **Marker tables and per-population contrasts.** A comparison can now have levels: `kind: markers` takes a marker table (Seurat `FindAllMarkers`, scanpy `rank_genes_groups`, presto, scran `findMarkers`, or a bare cluster-and-gene list from a paper) and makes one level per cluster, each against the rest, with `pct.1` / `pct.2` as a *% in / out* column; a `facet:` column, or `{level}` in the file names, splits a case/control result into one contrast per cell type with its own pseudobulk. Levels whose names are categories of an annotation are linked to it on their own: the panel gets a level select (`cmp=<id>:<level>`), a markers comparison shows *only <cluster>* instead of filtering the map, and each legend row of the annotation carries a *markers* button into that cluster's table. `init` recognises marker tables; `show()` gains `add_markers(adata)`, which reads `uns["rank_genes_groups"]`. Every comparison is now stored as `levels/<id>/` (existing comparisons rebuild once).
- **Docs by platform family.** The guide now opens with three pages, [sequencing-based](https://mictott.github.io/spatialscape/docs/guide/platforms/sequencing) (Visium, Visium HD, Slide-seq, Stereo-seq), [imaging-based](https://mictott.github.io/spatialscape/docs/guide/platforms/imaging) (Xenium, MERSCOPE, CosMx) and [single-cell](https://mictott.github.io/spatialscape/docs/guide/platforms/single-cell), each the minimal yaml for that family and then its optional layers with their files and costs, plus a table of what each family can show. Genome tracks and metadata/comparisons left `dataset.yaml` for pages of their own, and the sidebar is grouped (Start, By platform, Your dataset, Advanced, Sharing).
- **Other platforms' tables.** Cell boundaries, other segmentations and molecules are read from CSV and TSV (gzipped or not) as well as Parquet, streamed a block at a time; a cell id of 0 (NanoString) or −1 (Vizgen) counts as unassigned, a `CellComp` label of `Nuclear` as in the nucleus, and `Blank-*`, `NegPrb*`, `SystemControl*` and `FalseCode*` features are dropped as controls like 10x's. `init` on a Xenium `outs/` layout writes `polygons:` and `molecules:` for the tables it finds next to the matrix (as `{dir}` templates, one per glob match) and names the sample after the run folder rather than `outs`; on other imaging platforms it writes both keys as comments with the column names to fill in.
- **Plainer names in the side panel.** Transcripts: *selected genes* (the gene on screen and the pins) replaces *follow colour*. Cells: *Draw cells as* (dots, filled, outlined) replaces *Shapes* (dots, filled, edges), and *Annotation boundaries* replaces *Outlines*, which read as the cells' outlines one row above it. `cs=outlined` in the URL; `cs=edges` in older links still works.
- **Compare segmentations.** `segmentations:` on a sample lists other boundary sets of the same section (a long-format table like `polygons`, the polygons' `affine` inherited); a Xenium `nucleus_boundaries.parquet` next to the cell boundaries is taken automatically. Each is tiled like the cell shapes into `segmentations/<id>/shapes.*`, with its median ring area. In the viewer, *Compare with* in the Cells group draws one of them as dashed amber edges over the cells, image and molecules once zoomed in (URL `ov`), with a table of cells and median area for the focused section (or all sections) against the cells' own shapes.

## 0.4.0 (2026-10-23)

- **The side panel is five groups.** Image, Cells, Transcripts, Selections and Samples, each a bar that opens its controls; closed bars carry a one-line summary (the gene on screen, "GAD1 · 2 pinned", "2 sections · grid"), several can be open at once, what is open is remembered per browser, and Image and Transcripts carry their switch in the bar. Cells holds colour, legend, filter and a *Drawing* block (shapes once zoomed in, annotation outlines, cluster labels); the grid/strip layout moved into Samples. **Pinned molecule genes:** the Molecules row lists the gene on screen and any number of pinned genes, each in a fixed colour, so zoomed in several genes' molecules show at once while the cells still show the one gene (URL `mg`); *all genes* colours every gene by its own hue (`mc=all`). The molecule budget is set from measurements (a frame costs about 9 µs per thousand molecules on an M1 Max): a view draws every molecule it holds up to about one per screen pixel, a million in a large window, and a size slider scales the points (`msz`).
- **Images in a transposed export.** `transpose` and `flip` on an image entry put the image into the coordinates' frame before the sample's `transform`, for objects whose coordinates were transposed after the image was written (the amygdala's Br9206 and Br9192 Xenium sections now carry their DAPI).
- **Molecules.** `molecules: { path: transcripts.parquet }` on a Xenium sample tiles the individual transcripts (10x column names by default, Q20 and control-feature filters, the polygons' `affine` inherited), read one row group at a time: a 100 M-molecule amygdala section takes 40 s and 340 MB, 3.5 B per molecule, in 128 µm tiles sorted by gene and Morton order. The viewer draws them once a view holds about one per ten screen pixels (*molecules when zoomed in* in the Display panel, URL `mol=1`), in the colour on screen: the gene you look at, a blend's two sets, or grey under an annotation; unassigned molecules draw dimmer and the dots fade under them. Shapes and molecules share one tile manager (fetch once the camera settles, 64 tiles across panes, caches of 128 and 256 MB, results of a previous dataset dropped).
- **Cell shapes in tiles.** Cell boundaries are cut into square tiles of up to 1 mm (`shapes.json` + `shapes.bin`, or one file per tile with `--no-shard`), each ring tagged with its cell, so the viewer fetches only the tiles in view instead of a whole section's outlines: a 250k-cell amygdala section is 10 MB (44 B per cell, against about 25 MB before) and draws in about 1 ms per frame at the busiest view, where the whole-section outlines took about 29 ms. Shapes now take the cell's colour (gene, annotation, blend, filter, hidden categories) instead of plain white, and replace the dots once a cell is about 6 px across. *Cells when zoomed in* (dots, filled, edges; URL `cs`) replaces the boundaries checkbox; filled is the default without an image, edges over one. Tiles are requested only once the camera settles, at most 64 across all panes and 40,000 cells per pane (otherwise the status line says to zoom in), adjacent tiles in one byte-range request, and a host that ignores Range is reported instead of sending the whole file. Rings of cells removed by QC are dropped and counted; when some cells have no shape, the dots stay under the shapes so no cell vanishes. Spatial samples rebuild once on their next build; bundles built before still draw their old polygons.
- **Xenium morphology no longer loads a whole slide.** A Xenium outs folder's morphology image, found on its own with `images: auto`, used to be read at full resolution (about 6.5 GB for a public Prime mouse brain, about 11 GB per channel for a full section) or to fail on JPEG 2000. It is now read at about 0.85 µm per pixel, four times coarser than the scan (the 4-channel mouse brain is an 8,538 x 5,978 px copy, 214 MB on disk, and builds in 11 s), read at the next coarser level on a machine without the memory for it, found in the XOA 2+ `morphology_focus/` folder as well as XOA 1's single file, never the 3D z-stack, and placed with the pixel size from `experiment.xenium`. JPEG 2000 needs the new optional extra `spatialscape[images]` (imagecodecs); without it a discovered image is skipped with a note naming the extra, and a listed one stops the build with the same advice.
- **Image tiles are fetched once.** The viewer rebuilt its layers on every camera frame with new but equal settings, and Viv took each rebuild as a reason to drop its tile cache and download every visible tile again: two wheel gestures on the mouse brain made 2,820 tile requests for 44 distinct tiles, and sharper tiles waited up to 15 s behind the repeats. The settings now keep their identity while unchanged, so the same gestures make one request per tile, tiles settle within a frame or two, and areas already seen cost nothing. An image switched off, or with every channel hidden, keeps its tiles while hidden. The dev server keeps connections open (HTTP/1.1), every image chunk is written even when empty (a static host answers a missing one with 403, which blanked the whole tile; samples with an image rebuild once to get them), and JPEG 2000 sources decode on every core the build may use.
- **Image channels.** A multichannel image lists its channels under the image opacity slider, like the legend: click to switch one off or on, double-click to show it alone. Channels are matched by name across samples, switching downloads nothing, and the choice travels in the URL (`hc`).
- **`max_size` bounds memory for every image.** A file without pyramid levels (every Visium CytAssist and Visium HD TIFF from 10x) is reduced band by band while it is read, so a 3 GB immunofluorescence TIFF no longer has to fit in memory whole. An image read larger than a sixth of the machine's memory (or of its cgroup or SLURM limit) is refused with the size it needs and `max_size` as the way out. Multichannel images get names from the OME metadata, distinct colours and display windows fitted to the signal, so 16-bit fluorescence is no longer drawn nearly black; a `channels:` list of the wrong length is reported; the viewer draws the first six channels. A pyramid whose levels are 4x apart (some slide scanners write them so) no longer fails when its level 0 has to be reduced.

- **Comparisons in the bundle.** A `comparisons:` block takes the results of differential expression tests fit upstream (a results table, the per-replicate pseudobulk values and an optional replicate sheet, as DESeq2, limma, edgeR, Seurat, pyDESeq2 or scanpy write them), recognises the columns (or takes `columns:`), picks the gene column that matches the bundle best, sorts the table by padj, links each replicate to its sections through the samples' metadata and finds the split key from the groups, and writes `comparisons/<id>/` (results.json, pseudobulk.zarr, comparison.json) plus a manifest entry. Rebuilt only when a table, a setting or the samples change; `--dry-run` lists them; `validate` checks them. `init` turns a results table on the command line into an entry with the groups read from a `<case>_vs_<reference>` file name; `synth --comparisons` writes a complete example with three planted genes.
- **The Compare panel.** Choosing a comparison (a *Compare* section in the side panel, `cmp` in the URL) splits the canvas by its groups unless another split is pinned, applies its population as the category filter with a chip to clear it, and opens a panel under the maps: the results table on the left (sortable by any column, a direction filter, a search box, rows coloured by effect, unmeasured genes greyed; a click colours every pane by the gene, `↑`/`↓` step through the table) and, on the right, one dot per replicate for the gene on screen in the groups' colours with a median line, optional quartile boxes, lines between paired subjects, hover for the replicate's value and sections and a click to focus its section, plus the table's numbers for the gene and the comparison's description. The panel resizes from its top edge and stacks above the genome panel. From a notebook, `show(adata, meta={...})` declares the sample metadata and `s.add_comparison(name, results, pseudobulk, replicates, ...)` (or `show(..., comparisons=[...])`) puts a test's tables into the session's bundle without rebuilding the object, so a lasso, a test and its results next to the tissue is one loop.
- **Compare groups side by side.** Samples carry metadata (`meta: { condition: stress, mouse: m1 }`, a value per sample, typed or read from an obs column that is constant within the sample; optional dataset-level `meta:` for names and level order), and the viewer splits the tissue canvas by any key: one pane per level, two or three at a time, each with its own camera, caption, scale bar and focus, a select per pane when there are more groups than panes, draggable handles, vertical stacking on narrow windows, and *match scale* (on by default) keeping every pane at the same microns per pixel while each keeps its own centre. Colour, filters, legend, lasso and regions stay shared; sections without a value are left out and counted in the top bar; the hover shows the metadata; the split, groups, handles and cameras travel in the URL (`sb`, `sg`, `sf`, `ms`, `pv`); PNG export draws the captions; each pane has its own point-size slider (`psg` in the URL), a double-click returning a group pane to the shared value. Internally the canvas is now a list of panes rather than a fixed tissue/embedding pair; the embedding pane behaves as before. `init` proposes `# meta:` lines for columns that are constant within each sample; `synth --comparisons` writes a two-group example. A bare dataset name in `?d=` resolves against the page like a path.

## 0.3.0 (2026-10-21)

- **ATAC and multiome.** A sample with a Cell Ranger fragment file can carry `tracks:`: `build` streams the fragments once and writes bigWigs of insertions per million, binned, for every cell and per category of the fields you name, plus the sample's peaks and gene models (from the reference's GTF, a UCSC genePred table, a BED, or UCSC RefSeq downloaded once with the default `genes: refseq`). Needs `pip install "spatialscape[tracks]"`.
- **Genome panel.** An ATAC sample opens a genome panel under the maps, drawn by the viewer's own renderer: scroll to zoom, drag to pan, one accessibility track per visible category of the annotation last colored by on a shared scale, peaks, and gene models with exons and strand arrows. The locus follows the gene or peak you color by; one search box takes gene names or loci; clicking a gene or a peak colors the maps by it; the locus travels in the URL as `gl`, and the panel resizes from its top edge.
- **`spatialscape.show(adata)`.** Look at an object from the session you are in: an in-memory AnnData (or a path, R object, yaml or bundle) is built straight from memory into a content-keyed cache and shown in the notebook (or `.url` elsewhere) from a server thread in the process. `s.selection()` returns the cells inside the last lasso as obs names (or a mask), ready for a DE test; the viewer posts selections to the session's own server and to nothing else. Works from R through reticulate and one `saveRDS`.
- **Regions in a notebook.** The session keeps the drawing (polygons included), the viewer restores it when it reopens, and `s.save_regions(path)` / `s.load_regions(path)` / `show(..., regions=path)` keep it with the analysis across kernels.
- **Regions.** Draw your own annotation in the viewer: groups of lassos across sections (or the embedding), shown as labelled translucent polygons that stay attached to their section, switched with a click or keys 1–9, undone with Backspace. The groups are a live "Regions" annotation: colour by it, legend counts, hover, dot plot, filters. Export `sample, cell_id, region` as CSV, save and load the drawing as JSON, and in a notebook `s.regions()` returns it as a Series aligned with the object.
- **Repository review (six independent passes) and the fixes that followed.** Build: an incremental build now commits each sample's `build.json` only after the manifest it was encoded against is written, so a run that dies mid-way cannot leave a sample whose category codes decode against the wrong vocabulary; integer and float spellings of the same label (`1` / `1.0`) meet in one category; more than 65,535 categories is a clear error; all-integer matrices are counts regardless of their maximum; NaN or infinite expression is refused with the offending features named; `validate` now checks id blocks, the obs order permutation, categorical and continuous array lengths, listed outline files, polygon offsets and finite gmax. Inputs: R rasters decode row-major; the literal label `NA` survives; NA logicals stay missing; R integer columns stay integers (nullable) and integer cluster ids become annotation candidates in `init`; a Visium HD sample refuses the Visium spot-spacing rule instead of silently scaling by the bin pitch; `images: auto` accepts any `tissue_<id>_image.png`; 4-channel fluorescence stacks keep their 4th channel; image shapes come from file headers; mito columns that already say percent are not scaled again; YAML-typed scalars are quoted in menus; `**` globs recurse; flat `samples/*.h5ad` layouts get unique default ids. Serving: one bad manifest no longer breaks the generated gallery; the dev server answers 416 to inverted ranges, 200 to multi-range requests, 400 to malformed POSTs, no longer lists bundle folders, and declares its MIME types properly. `show()`: the cache hash covers the columns the menu maps (re-clustering rebuilds), backed objects hash by file, and a stale lock is claimed atomically. Tracks: gaps between bins are written as zero runs so zoomed-out bigWig summaries are area-correct, bins end at the chromosome end, duplicate slugs are disambiguated, Signac-style `chr1-100-200` peak names are recognised, and per-chunk accumulation uses `bincount`. CI installs the `tracks` extra and runs the tests before a release. Viewer: loading another dataset into the same page disposes the previous worker, arrays, scales, caches, selection, regions and counts; requests are deduplicated in flight; the lasso rejects browser shortcut chords; hover reports only drawn cells; hide-zeros and blends handle signed features; the filter histogram respects hidden samples; regions no longer recompute on colour-picker ticks, invalidate category-filter masks, validate imported JSON, keep names unique and remap hidden/filter codes when a group is removed; image opacity and visibility travel separately in the URL (`img`, `imgs`) and feature ids containing colons round-trip in filters; URL writes are debounced within browser limits; the genome panel keeps one data array per track (no re-tesselation while panning), glides on inertia, keeps the finer of two racing fetches, labels ticks 1-based, reports unreadable tracks, and no longer jumps back to the default gene when you switch to an annotation.
- Viewer: a feature group's list shows at most 200 rows plus the current feature (type to narrow), and group membership is indexed once. A 354k-peak group used to put 354k nodes in the page and slow every click.
- Build: an image several sections share (one slide image under two Visium HD sections, detected as identical files in sibling sample folders, or `mask: true`) is blanked beyond 150 µm of each section's own points, so the neighbour's tissue no longer shows up under a sample with no cells on it. Viewer: an image with a single pyramid level (a small crop) rendered nothing, Viv's single-level layer being handed the whole pyramid array. H&E and fluorescence images are cropped to the points' bounding box plus a 3% margin by default (`crop: false` keeps the whole scan), so a slide image no longer sets the size of a sample's grid cell and the pyramids are smaller; objects whose `var_names` are Ensembl ids are named by their `gene_name` / `symbol` column on their own; an S4 slot holding NULL (stored as the `\001NULL\001` symbol) reads as NULL, which is why spatialLIBD objects came out with `gene0, gene1, …` feature names. R-object conversion caches are redone once (cache version 3).
- **Track normalization.** `tracks.normalize` chooses what each group's track is scaled by: `nfrags` (per million insertions, the default), `tss` (per million insertions within `tss_window` bp of a gene TSS, ArchR's ReadsInTSS, robust to groups with noisier libraries) or `cells` (per nucleus); the panel's scale label follows. BigWig intervals now merge equal neighbours, and the docs recommend `bin: 100` for dense pooled data.
- **Genome panel smoothing.** Lanes are drawn through a rolling mean (200 bp by default, a control in the panel header: raw, 100, 200, 500 or 1000 bp), the same for every lane, so a single noisy bin of a small group no longer sets the shared scale that every other lane is drawn against.
- **R objects are read by spatialscape's own reader** (`rdsread.py`, XDR format, gzip/bzip2/xz): it streams the file once, decodes uniform string vectors in bulk (an H&E raster is a numpy array, not millions of strings), walks past closures, environments and bytecode, and skips slots nobody needs (`scale.data`, graphs, commands). A 0.75 GB Visium HD SpatialExperiment with ten H&E images reads in 8 s; rds2py and rdata are no longer dependencies.
- **First-run review fixes (four reviewer passes as new users).** Commands exit with status 1 when they report problems (`validate`, a failing `build`); the dataset yaml has `sharded:` so a bundle built for GitHub Pages stays unsharded through `site build` and later builds (`--no-shard` sets it for one run and says so; the plan reports \"sharding changed\"); a published site no longer carries `build.json` fingerprints or the config path from the building machine; the viewer's `favicon.svg` ships with the package; `synth` prints the next command; the coordinate scale is checked before any expression is written, and logged; the build log says why a layer was taken as counts or log-normalized and how many all-zero features were left out, and the manifest records `expr.normalized`; `s.selection()` warns when obs names repeat across samples. Viewer: the dot plot's column headers line up; the gene box says \"no gene named X\" and falls back to the gene on screen; copy link says when the link is local to this computer and when copying failed; a category filter hides nothing until a category is picked; the filter's gene defaults to the one on screen; Shift+L also opens the lasso.
- **First-run review fixes, batch 2: nothing assumed in silence.** `init` guesses the platform from the columns (`array_row` / `array_col` mean Visium when the grid fits one Visium array or the spots split into capture areas of Visium size, Visium HD when the grid is larger; Xenium's cell metrics mean Xenium; otherwise `visium`), says so in the yaml's `platform:` comment ("guessed from ...", "given", or "the default") and prints an "assumed for" block per entry: platform, what the coordinates are taken to be, which layer or assay is drawn and how normalization is decided, and the mapped columns with their level and NA counts. Column notes carry NA counts. A single file that holds several sections (a `sample_id` / `capture_area` column) gets a warning and a commented `subset:` line. The "cannot infer microns" error names the shortcuts (`platform: xenium`, `already_microns`, Visium HD's `microns_per_unit`). New `overrides:` on glob and R-object entries changes single samples (`{ Br9902_1: { images: [] } }`; dicts merge, lists replace, an unknown name is an error). `images: []` or a listed image no longer loses the SpaceRanger scale factors next to the sample.
- **First-run review fixes, batch 3: the docs say what happens.** Getting started is organised by goal (look at an object, view your data locally, publish), the install section has the from-source route for the development version, the commands match the folder tree they draw (`init` writes the yaml where it runs), and the time estimates are honest. Publishing has one complete GitHub Pages route (branch, push, settings, `validate`; `site build` now writes `.nojekyll`), an S3 + CloudFront setup whose variables are all defined and whose bucket policy is a command, and uploads one bundle folder at a time so `.cache/` stays home. The viewer guide describes the Outlines section and the selection's "vs … overall" numbers as they are, says that every gene number the viewer shows is reconstructed from 8-bit storage, and that a link copied from a local server is local. The notebook guide says a plain script must keep running for the viewer to stay up and shows `s$selection(as_mask = TRUE)` from R.
- **Seurat objects.** `init`, `build` and `inspect` read a Seurat object (`.rds` / `.rda`) directly, no R needed: v3 to v5 assays, split v5 layers joined back, `meta.data` and the active ident as `obs`, reductions by name. The gene assay is drawn as expression (`assay:` picks the layer, `data` by default) and every other assay becomes prefixed features next to the genes: `peak: ` for a Signac ChromatinAssay or coordinate-named features, `activity: `, `motif: `, `<assay>: `. `inspect` prints the fragment files a ChromatinAssay points at. Seurat spatial images are not read yet. R objects are now parsed with the pure-Python `rdata` package instead of `rds2py`, so the functions, environments and bytecode an object carries (Seurat records them in `@commands`) no longer abort the parse.
- **Tracks for pooled objects, and from bigWigs you already have.** `tracks.fragments` takes one file per run (`{run: file}` with `sample_column`): each observation is matched to the fragments of its own run, so colliding 10x barcodes stay apart, and a category's track sums its cells over every run before the per-million scaling; observation names like `Br2743#AAAC…-1` are understood without a `barcode_column`. `tracks.bigwigs` copies in per-group bigWigs exported by ArchR, Signac or bamCoverage (`{label}` templates or files listed per label, raw labels matched through the field's aliases, optional `all`), reads their bin size, takes chromosome names from the files for an unknown genome, and the panel's scale shows `units`. A fragment file may be `ssh://host/path`: it is streamed through ssh while the tracks are counted and never stored locally, and the fingerprint asks the host for its size and date. Samples with tracks are rebuilt once (new settings).
- **Faster, lighter builds.** The expression writer quantizes only the stored values and scatters them, through the LOD shuffle, into shards it writes directly in zarr's layout (zstd in threads), instead of densifying each shard to float32 and feeding zarr-python one gene chunk at a time; log-normalization scales the stored values in place rather than through a sparse product; gene ranges and variances come straight from the CSC structure without scipy's index sort. The h5ad reader loads only the layer, `obs`, `var` and `obsm` keys a sample uses, and pyramidal images are read at the level `max_size` asks for and downsampled in strips. A 14.6k-cell × 36.6k-gene snRNA-seq object builds in 3.6 s instead of 18 s; seven Visium donors with H&E in 29 s instead of 85 s, with peak memory down from 5.5 GB to 3.3 GB.
- Fixed: H&E images read from an R object (`LoadedSpatialImage` rasters) came out as vertical streaks. R rasters are stored row by row, unlike other R matrices; the decoder assumed column order. Conversions are redone once (cache version bumped).
- Features that take negative values (module scores, motif deviations) keep their sign: a symmetric scale centred on zero with a diverging colormap.
- Example: `examples/pbmc_multiome.yaml` and `examples/scripts/pbmc_multiome.py` build the public 10x PBMC multiome (RNA and ATAC embeddings of the same nuclei, gene activity, marker-set scores, the most variable peaks, and genome tracks).

## 0.2.0 (2026-10-14)

- **Two yamls and one command.** `spatialscape init` now writes a dataset yaml that is a menu of the data: it reads an R object or the first file of a glob, maps the columns that look like spatial domains, cell types and QC metrics, lists every other column as a comment, declares display names for the mapped fields and sets `default_color`. R objects (`.rds` / `.rda`) are listed directly under `samples:` (`path:` plus optional `assay`, `sample_col`, `embedding`, `object`) and converted by `build` into `bundles/.cache/<id>/` on first use. `build` is incremental: each sample folder carries `build.json`, and a rerun rebuilds only samples whose source files, settings or field declarations changed, removes samples the yaml dropped, and always rewrites the dataset-level files, so renames, palettes and defaults apply in seconds (`--dry-run` shows the plan, `--force` rebuilds all). Output defaults to `bundles/<id>` next to the yaml. The gallery is described in `site.yaml` (`site init`, `site build site.yaml`): title, intro, `nav`, `data_url`, and cards from dataset yamls (built when stale), built bundles or placeholders; `datasets.json` is now a pure build output. Removed: `convert` (list the object under `samples:`), `plan` (`build --dry-run`), `refresh` and `add-sample` (`build`), and the `--title/--intro/--data-url` flags of `site build` (keys in `site.yaml`). The gallery heading is the registry's `title`; `thumbnail_sample` is honoured by `build` and by `thumbnails` without `--hero`.
- **The viewer ships in the Python package.** `spatialscape serve` serves the viewer, a gallery generated from every bundle in the folder, and the data from one local address; `--open` launches the browser. New `spatialscape site build` writes a deployable folder (viewer + `datasets.json` + bundles, or `--data-url` for bundles on object storage) and preserves hand edits to the registry.
- `spatialscape convert` reads SpatialExperiment / SingleCellExperiment objects straight from `.rds` / `.rda` (parsed in Python with rds2py, no R needed) and writes build inputs: one SpaceRanger-like folder per sample with the H&E and scale factors, or one h5ad with the UMAP for snRNA-seq references. `inspect` reads R objects too.
- CLI: readable one-line errors (traceback behind `SPATIALSCAPE_DEBUG=1`), `--version`, `init` picks the right template for file-per-sample and folder-per-sample layouts, `inspect` no longer crashes on files without layers, `validate <url>` sends an `Origin` header and requires Range support only for sharded bundles. Config paths expand `${ENV_VAR}`.
