# Changelog

## Unreleased

- **ATAC and multiome.** A sample with a Cell Ranger fragment file can carry `tracks:`: `build` streams the fragments once and writes bigWigs of insertions per million, binned, for every cell and per category of the fields you name, plus the sample's peaks and gene models (from the reference's GTF, a UCSC genePred table, a BED, or UCSC RefSeq downloaded once with the default `genes: refseq`). Needs `pip install "spatialscape[tracks]"`.
- **Genome panel.** An ATAC sample opens a genome panel under the maps, drawn by the viewer's own renderer: scroll to zoom, drag to pan, one accessibility track per visible category of the annotation last colored by on a shared scale, peaks, and gene models with exons and strand arrows. The locus follows the gene or peak you color by; one search box takes gene names or loci; clicking a gene or a peak colors the maps by it; the locus travels in the URL as `gl`, and the panel resizes from its top edge.
- **`spatialscape.show(adata)`.** Look at an object from the session you are in: an in-memory AnnData (or a path, R object, yaml or bundle) is built straight from memory into a content-keyed cache and shown in the notebook (or `.url` elsewhere) from a server thread in the process. `s.selection()` returns the cells inside the last lasso as obs names (or a mask), ready for a DE test; the viewer posts selections to the session's own server and to nothing else. Works from R through reticulate and one `saveRDS`.
- **Regions in a notebook.** The session keeps the drawing (polygons included), the viewer restores it when it reopens, and `s.save_regions(path)` / `s.load_regions(path)` / `show(..., regions=path)` keep it with the analysis across kernels.
- **Regions.** Draw your own annotation in the viewer: groups of lassos across sections (or the embedding), shown as labelled translucent polygons that stay attached to their section, switched with a click or keys 1–9, undone with Backspace. The groups are a live "Regions" annotation: colour by it, legend counts, hover, dot plot, filters. Export `sample, cell_id, region` as CSV, save and load the drawing as JSON, and in a notebook `s.regions()` returns it as a Series aligned with the object.
- **Repository review (six independent passes) and the fixes that followed.** Build: an incremental build now commits each sample's `build.json` only after the manifest it was encoded against is written, so a run that dies mid-way cannot leave a sample whose category codes decode against the wrong vocabulary; integer and float spellings of the same label (`1` / `1.0`) meet in one category; more than 65,535 categories is a clear error; all-integer matrices are counts regardless of their maximum; NaN or infinite expression is refused with the offending features named; `validate` now checks id blocks, the obs order permutation, categorical and continuous array lengths, listed outline files, polygon offsets and finite gmax. Inputs: R rasters decode row-major; the literal label `NA` survives; NA logicals stay missing; R integer columns stay integers (nullable) and integer cluster ids become annotation candidates in `init`; a Visium HD sample refuses the Visium spot-spacing rule instead of silently scaling by the bin pitch; `images: auto` accepts any `tissue_<id>_image.png`; 4-channel fluorescence stacks keep their 4th channel; image shapes come from file headers; mito columns that already say percent are not scaled again; YAML-typed scalars are quoted in menus; `**` globs recurse; flat `samples/*.h5ad` layouts get unique default ids. Serving: one bad manifest no longer breaks the generated gallery; the dev server answers 416 to inverted ranges, 200 to multi-range requests, 400 to malformed POSTs, no longer lists bundle folders, and declares its MIME types properly. `show()`: the cache hash covers the columns the menu maps (re-clustering rebuilds), backed objects hash by file, and a stale lock is claimed atomically. Tracks: gaps between bins are written as zero runs so zoomed-out bigWig summaries are area-correct, bins end at the chromosome end, duplicate slugs are disambiguated, Signac-style `chr1-100-200` peak names are recognised, and per-chunk accumulation uses `bincount`. CI installs the `tracks` extra and runs the tests before a release. Viewer: loading another dataset into the same page disposes the previous worker, arrays, scales, caches, selection, regions and counts; requests are deduplicated in flight; the lasso rejects browser shortcut chords; hover reports only drawn cells; hide-zeros and blends handle signed features; the filter histogram respects hidden samples; regions no longer recompute on colour-picker ticks, invalidate category-filter masks, validate imported JSON, keep names unique and remap hidden/filter codes when a group is removed; image opacity and visibility travel separately in the URL (`img`, `imgs`) and feature ids containing colons round-trip in filters; URL writes are debounced within browser limits; the genome panel keeps one data array per track (no re-tesselation while panning), glides on inertia, keeps the finer of two racing fetches, labels ticks 1-based, reports unreadable tracks, and no longer jumps back to the default gene when you switch to an annotation.
- Viewer: a feature group's list shows at most 200 rows plus the current feature (type to narrow), and group membership is indexed once. A 354k-peak group used to put 354k nodes in the page and slow every click.
- **Seurat objects.** `init`, `build` and `inspect` read a Seurat object (`.rds` / `.rda`) directly, no R needed: v3 to v5 assays, split v5 layers joined back, `meta.data` and the active ident as `obs`, reductions by name. The gene assay is drawn as expression (`assay:` picks the layer, `data` by default) and every other assay becomes prefixed features next to the genes: `peak: ` for a Signac ChromatinAssay or coordinate-named features, `activity: `, `motif: `, `<assay>: `. `inspect` prints the fragment files a ChromatinAssay points at. Seurat spatial images are not read yet. R objects are now parsed with the pure-Python `rdata` package instead of `rds2py`, so the functions, environments and bytecode an object carries (Seurat records them in `@commands`) no longer abort the parse.
- **Tracks for pooled objects, and from bigWigs you already have.** `tracks.fragments` takes one file per run (`{run: file}` with `sample_column`): each observation is matched to the fragments of its own run, so colliding 10x barcodes stay apart, and a category's track sums its cells over every run before the per-million scaling; observation names like `Br2743#AAAC…-1` are understood without a `barcode_column`. `tracks.bigwigs` copies in per-group bigWigs exported by ArchR, Signac or bamCoverage (`{label}` templates or files listed per label, raw labels matched through the field's aliases, optional `all`), reads their bin size, takes chromosome names from the files for an unknown genome, and the panel's scale shows `units`. Samples with tracks are rebuilt once (new settings).
- **Faster, lighter builds.** The expression writer quantizes only the stored values and scatters them, through the LOD shuffle, into shards it writes directly in zarr's layout (zstd in threads), instead of densifying each shard to float32 and feeding zarr-python one gene chunk at a time; log-normalization scales the stored values in place rather than through a sparse product; gene ranges and variances come straight from the CSC structure without scipy's index sort. The h5ad reader loads only the layer, `obs`, `var` and `obsm` keys a sample uses, and pyramidal images are read at the level `max_size` asks for and downsampled in strips. A 14.6k-cell × 36.6k-gene snRNA-seq object builds in 3.6 s instead of 18 s; seven Visium donors with H&E in 29 s instead of 85 s, with peak memory down from 5.5 GB to 3.3 GB.
- Fixed: H&E images read from an R object (`LoadedSpatialImage` rasters) came out as vertical streaks. R rasters are stored row by row, unlike other R matrices; the decoder assumed column order. Conversions are redone once (cache version bumped).
- Features that take negative values (module scores, motif deviations) keep their sign: a symmetric scale centred on zero with a diverging colormap.
- Example: `examples/pbmc_multiome.yaml` and `examples/scripts/pbmc_multiome.py` build the public 10x PBMC multiome (RNA and ATAC embeddings of the same nuclei, gene activity, marker-set scores, the most variable peaks, and genome tracks).

## 0.2.0 (2026-10-14)

- **Two yamls and one command.** `spatialscape init` now writes a dataset yaml that is a menu of the data: it reads an R object or the first file of a glob, maps the columns that look like spatial domains, cell types and QC metrics, lists every other column as a comment, declares display names for the mapped fields and sets `default_color`. R objects (`.rds` / `.rda`) are listed directly under `samples:` (`path:` plus optional `assay`, `sample_col`, `embedding`, `object`) and converted by `build` into `bundles/.cache/<id>/` on first use. `build` is incremental: each sample folder carries `build.json`, and a rerun rebuilds only samples whose source files, settings or field declarations changed, removes samples the yaml dropped, and always rewrites the dataset-level files, so renames, palettes and defaults apply in seconds (`--dry-run` shows the plan, `--force` rebuilds all). Output defaults to `bundles/<id>` next to the yaml. The gallery is described in `site.yaml` (`site init`, `site build site.yaml`): title, intro, `nav`, `data_url`, and cards from dataset yamls (built when stale), built bundles or placeholders; `datasets.json` is now a pure build output. Removed: `convert` (list the object under `samples:`), `plan` (`build --dry-run`), `refresh` and `add-sample` (`build`), and the `--title/--intro/--data-url` flags of `site build` (keys in `site.yaml`). The gallery heading is the registry's `title`; `thumbnail_sample` is honoured by `build` and by `thumbnails` without `--hero`.
- **The viewer ships in the Python package.** `spatialscape serve` serves the viewer, a gallery generated from every bundle in the folder, and the data from one local address; `--open` launches the browser. New `spatialscape site build` writes a deployable folder (viewer + `datasets.json` + bundles, or `--data-url` for bundles on object storage) and preserves hand edits to the registry.
- `spatialscape convert` reads SpatialExperiment / SingleCellExperiment objects straight from `.rds` / `.rda` (parsed in Python with rds2py, no R needed) and writes build inputs: one SpaceRanger-like folder per sample with the H&E and scale factors, or one h5ad with the UMAP for snRNA-seq references. `inspect` reads R objects too.
- CLI: readable one-line errors (traceback behind `SPATIALSCAPE_DEBUG=1`), `--version`, `init` picks the right template for file-per-sample and folder-per-sample layouts, `inspect` no longer crashes on files without layers, `validate <url>` sends an `Origin` header and requires Range support only for sharded bundles. Config paths expand `${ENV_VAR}`.
- Build: polygons from `obsm` arrays (auto-detected) or long-format parquet with an `affine` frame mapping and a centroid sanity check; long-form field maps `{column, scale}`; `refresh` re-applies palette colors; per-crop micron scales for Visium HD.
- Viewer: shared gene color scale across samples (per-sample as an option), blend = mean log-normalized expression, per-view point size, PNG export with legend and scale bar, copy-link button, recent genes, `?` shortcut overlay, legends sorted by count with a "not measured" note, label de-collision, grid cells that include image frames, collapsed sample list, telemetry behind `?debug=1`.
- Docs: VitePress site with a generated per-command CLI reference; "Publish your own site" guide.
- Registry: public `datasets.json` plus a gitignored `datasets.local.json` overlay for development.

First public version.

- Viewer: one-canvas mosaic/strip of all samples with focus and keyboard stepping; gene, annotation and feature-group coloring; legend filtering; independent filter channel (gene, continuous, categorical); hover with all annotations; lasso selection with composition, gene statistics and CSV export; expression-by-annotation dot plot; domain outlines; cell polygons at high zoom; H&E / fluorescence images via Viv; platform bar; linked snRNA-seq embedding split view; full URL state.
- CLI (`spatialscape`, alias `sscape`): `inspect`, `build`, `add-sample`, `refresh`, `outlines`, `validate`, `serve`, `synth`. Sharded Zarr v3 uint8 expression, dataset-level vocabularies, OME-Zarr images, outline tracing, polygon packing.
